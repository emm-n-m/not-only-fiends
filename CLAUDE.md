# CLAUDE.md

See `AGENTS.md` for project architecture, commands, design decisions, assertion discipline, and
external-data safety rules. Those instructions apply to Claude Code too.

## Skills and agents

The shared skill source is `agent-skills/skills/`. `.claude/skills/` is generated by
`tools/sync_agent_skills.py`; never edit a projected skill directly. Claude-only frontmatter
belongs in the canonical skill's `platforms/claude.frontmatter` file.

Custom subagents in `.claude/agents/` are deliberately thin adapters:

- `content-extractor` — orchestrates a complete source extraction.
- `content-qa` — validates changed content against schemas and tests.
- `gap-filler` — finds content gaps, extracts missing definitions, and validates the result.

Each adapter preloads the corresponding canonical workflow. Do not add unique domain rules or
session discoveries to an adapter; update the shared skill so Codex and Claude retain capability
parity.

After editing skills, run:

```bash
python3 tools/sync_agent_skills.py
python3 tools/sync_agent_skills.py --check
```

Outstanding engine/API work is tracked in `KNOWN_ISSUES.md`. Public SRD content gaps belong in
`CONTENT_GAPS.md`; private-pack gaps belong in the private materials repository.
